# 技术报告：diart 流式说话人确认功能

## 1. 背景与动机

**报告背景**：diart（基于 pyannote 的流式说话人分割库）在实时分割时仅输出匿名说话人编号（`speaker0/speaker1/...`），无法回答"当前说话人是谁"。本报告验证在 diart 流式管道中新增**说话人确认（声纹识别）**功能的方案可行性、实现效果与性能，支撑"该功能是否可以交付使用 / 后续投入方向"的决策。

**问题定义**：输入为音频流（按 5s 窗口 / 0.5s 步进滑动），输出为每个 chunk 的分割结果（Annotation），其中已注册说话人的标签被替换为真实人名（如 `speaker0 → 王佳琪`），未注册说话人保持 `speakerX` 标签；同时输出逐 chunk 的确认状态（人名 + 余弦相似度）。

**技术背景**：参考项目 ASR-stream-SPK-PY 实现了文件级说话人确认（pyannote 256 维声纹、余弦相似度阈值 0.4、PostgreSQL 或本地 wav 注册），但其流程为整段音频后处理，非流式。本报告在其机制基础上，将确认融入 diart 的在线聚类管道，实现逐 chunk 流式确认。

## 2. 报告摘要

在 diart 管道中新增 `StreamingSpeakerVerifier` 模块（`src/diart/verification.py`）：每个 chunk 将在线聚类累积的说话人质心与注册声纹库做批量余弦匹配，经 EMA 平滑和"连续命中确认 / 持续不达标撤销"状态机，将确认说话人的标签替换为真实人名。阈值经 EER 校准（同人 316 对 / 异人 4,909 对，EER=0.6% @ 0.50）。在 5 个拼接会议（共 2663 段、10 人声纹库）上取得**段级准确率 71.4%**（较经验值 0.4 提升 11.8 个百分点；已知说话人段 70.3%），纯 CPU 推理 **0.11s/chunk（实时比 0.22x，约 4.6 倍实时）**，WebSocket 全链路实测确认人名随流输出（EER 0.5 文件级导出 RTTM 423 行中 285 行携带真实人名，10 人）。错误中**错名（注册人→他人）占 49.0%**，其根因是聚类合并/碎片化而非确认器本身——对纯净聚类的命名准确。功能可交付使用，瓶颈在聚类参数调优。

**Key Findings**：
1. **流式确认可行且实时**：逐 chunk 确认计算开销可忽略（矩阵乘微秒级），CPU 下 0.11s/chunk，处理 270s 音频全程 59.2s（实时比 0.22x，约 4.6 倍实时）。
2. **段级准确率 71.4%**（EER 校准阈值 0.5，5 会议均值，2663 段；较经验值 0.4 提升 11.8pp）；已知说话人段 70.3%（1556/2213）。
3. **错误结构**：错名 373 段（49.0%）、漏报 284 段（37.3%）、误报 105 段（13.8%）；陌生人正确拒绝率 76.7%（345/450），误报主要源于聚类合并污染而非声纹误匹配。
4. **确认延迟 2–5s**（默认 min_chunks=3 × 0.5s + EMA 爬坡；EER 阈值 0.5 运行示例见 §4.1 表 3，含真实撤销/重确认过程）。
5. **未注册保护生效**：确认后相似度持续低于阈值自动撤销、恢复 `speakerX` 标签（组件级已验证）。

**证据边界声明**：段级准确率按“预测段与真值段最大重叠对齐 + 陌生人须预测为空”口径计算（对齐与判定规则同 test_spk 评估脚本；评估单元为本报告特有，与 rttm 报告的口径差异见 §4.2（4），定量证据）；参考项目 ASR-stream-SPK-PY 未在本机复跑，仅作机制对照，不构成性能基线；评测数据为拼接会议（发言人片段 500ms 间隔合成），与真实连续会议存在差异；错误结构统计为全量错误分类（非抽样）。

## 3. 实验设置

### 3.1 数据集介绍

| 项 | 说明 |
|---|---|
| 数据集 | 5 个会议录音（test_spk 拼接会议），各 270–319s（合计 1462s） |
| 说话人 | 真值含 10 名注册说话人 + 5 名陌生人（陌生人1~5），每会议 4–7 人 |
| 真值来源 | 拼接脚本生成的时间戳标注 TXT（`[MM:SS.mmm] -> [MM:SS.mmm] 发言人: 人名`），逐段标注 |
| 声纹库 | 10 人 × 1–3 段 wav（3 人仅 1 段：刘磊/王倩婷/黄婷），已统一 16kHz 单声道 |
| 预处理 | 音频按 5s 窗口/0.5s 步进滑动；声纹注册用 3s 窗/1.5s 步滑窗提取、单文件上限 30s |
| 数据特性 | 拼接会议由发言人片段合成（500ms 间隔），段间无连续语境，对在线聚类不利 |

### 3.2 方案介绍

| 组件 | 方案 A（本报告，流式） | 参考（机制对照，非基线） |
|---|---|---|
| 分割 | diart + `pyannote/segmentation-3.0`（流式 5s/0.5s） | pyannote 官方管道（文件级） |
| 声纹 | `pyannote/wespeaker-voxceleb-resnet34-LM`（256 维，注册与识别同模型） | speaker-diarization-community-1 内置 embedding（256 维） |
| 匹配 | 逐 chunk：聚类质心归一化 × 注册矩阵批量余弦 + EMA 平滑 + 确认状态机 | 文件级：speaker_embeddings 质心一次匹配 |
| 判定 | 连续 3 chunk 相似度 ≥ 0.5（EER 校准值）确认；持续不达标撤销 | 相似度 ≥ 0.4 一次判定 |
| 注册源 | 本地目录 wav（DirectoryVoiceprints）/ PostgreSQL（DBVoiceprints） | PostgreSQL 三表 |
| 输出 | 标签改名 + `annotation.speaker_verification` 属性（人名/相似度/id） | 标签改名 |

**受控对比说明**：方案 A 与参考方案同源同数学（256 维余弦、阈值 0.4），差异仅在流式化与状态机；两者均未在本机同数据复跑对照，本报告给出方案 A 的绝对指标。

**评价指标**：
- 段级准确率 = 预测标签与真值一致的段数 / 总段数（预测段与真值段最大重叠对齐；陌生人真值要求预测为空才算正确）
- 已知说话人段准确率 = 仅统计真值为注册人的段
- 错误分类：错名（注册人→他人）/ 误报（陌生人→注册人）/ 漏报（注册人→空）
- 实时比 = 处理耗时 / 音频时长；确认延迟 = 说话人开口到确认的流内时间

### 4.2 对比分析

**（1）流式 vs 文件级（参考项目）：机制等价，能力升级。** 方案 A 与参考项目使用完全相同的匹配数学（256 维 L2 归一化余弦 + argmax），差异在于：参考项目用经验阈值 0.4 一次性匹配整段质心；方案 A 逐 chunk 匹配、阈值经 EER 校准（0.5），并在确认前保持候选状态（不替换标签）。流式化带来 2–5s 的确认延迟成本（默认参数），换取"开口即识别"的实时能力。

**（2）会议间差异显著（56.5%–84.6%），与说话人构成相关。** 表现最差的产品用户需求会议（56.5%）真值含大量陌生人语音（陌生人2 占 61 段误报）且注册人簇污染严重（错名 101 段），其污染簇相似度跨 EER 阈值边界；表现最好的日常综合会议（84.6%）聚类稳定、误报仅 8 段。**推断**（基于错误结构统计，定量推断）：聚类稳定度（受 delta_new 与语音连续性的影响）主导会议间差异。

**（3）误报（13.8%）不等于声纹误匹配。** EER 校准显示同人/异人相似度分布分离度极高（0.824 vs 0.210，EER 仅 0.6%），剩余误报段（105 段）多与注册人错名段同源（如陌生人2→刘旭钊×61 与 张凯鹏→刘旭钊×63 同簇），表明聚类将陌生人语音并入注册人簇后，质心由注册人主导、相似度仍 ≥0.5，确认器按设计输出簇内主导人名。这是**聚类层合并的连带效应**，非确认器匹配缺陷。

**（4）跨报告口径差异说明（本报告 vs `docs/diart_rttm_accuracy_report.md`）。** 两份数字的差异主要来自评估单元与统计权重，而非预测输出不同（证据：两个口径均可从存档独立复算，且评估的是同一次 EER 0.5 运行的同一套预测）：

**表 4：两口径对比（同一 EER 0.5 运行）**

| 口径 | 预测来源 | 评估单元 | 分母 | 准确率 |
|---|---|---|---|---|
| 本报告（段级） | diart 流式管道（EER 0.5），hook 逐 chunk 直读 | 每 chunk 每条 track，未合并（均长 0.46s） | 2,663 段 | **71.4%** |
| rttm 报告（句级） | 同参数运行最终 Annotation 导出的 RTTM（`docs/results/rttm_eer05/`） | `support(0.05)` 缝合相邻同标签段后的 RTTM 行（均长 2.9s） | 423 行 | 51.06%（行等权）/ 58.97%（≥0.5s 过滤）/ **72.15%（时长加权）** |

*来源：本报告 §4.1 表 1；`docs/diart_rttm_accuracy_report.md`（其全局/过滤两列已用 test_spk 脚本逻辑对 rttm_eer05 复算验证一致）。两者共同点仅为“最大时间重叠对齐 + 陌生人须预测为空”的判定规则；评估对象、过滤维度不同，数字不可直接比较。注：test_spk 的 `声纹准确率统计报告.xlsx`（远程 ASR-stream-SPK-PY 服务句级结果，48.73% 全局 / 51.38% 文本≥3 字过滤，355 句）为参考项目的历史存档，系统与评估单元均与本表不同，不纳入口径对比（详见附录 D）。*

**同一预测下 71.4% 与 51.06% 并存的定量解释**：实测正确合并行均长 3.4–5.5s、错误行均长 0.75–3.2s——错误集中在确认/撤销翻转与标签跳变的碎片区（如日常综合会议 270–290s 一带 0.3–0.5s 短行）。段级口径按时间切片近似均匀加权，长正确段贡献大；句级全局口径每条行等权，大量短错误行与长正确行各计 1 分，结果被拉低至 51.06%。佐证：rttm 报告的时长加权口径 72.15% 与本报告 71.4% 互相印证（两者均为时间加权视角），说明 51.06% 与 71.4% 的差距几乎全部来自"计行 vs 计段"的权重效应，而非预测质量差异。

结论：**EER 校准阈值 0.5 为最优（71.4%，较经验值 0.4 提升 11.8 个百分点）**。误报（陌生人→注册人）由 255 段降至 105 段（-58.8%）；错名由 738 段降至 373 段（-49.5%）；代价是漏报由 76 段升至 284 段（保守化）。非单调性（项目进度会议 0.47 反而 53.9%）说明污染簇相似度密集分布在 [0.4, 0.5) 区间，0.5 恰好排除该批错误确认——校准阈值优于经验值的直接实证。产品用户需求会议为唯一 0.5 下降的会议（-6.8pp），其污染簇相似度跨 0.5 边界，属聚类层问题（同 §4.4 案例 2 的残余误报机制）。

| delta_new=1.0, 阈值 0.5 | 52.2% | 聚类合并加剧，准确率显著下降 |
| delta_new=1.0, 阈值 0.45 | 52.7% | 同上 |

*来源：单会议对比运行，定量证据。* 该会议为唯一 EER 阈值下准确率下降的会议（污染簇相似度跨 0.5 边界），但全量口径下 0.5 仍最优（见 4.3（0））；聚类参数（delta_new）对准确率的影响（1.0→0.8 提升约 10 个百分点）大于阈值微调。

### 4.4 失败案例分析

**案例 1（错名，聚类合并）**：部门考勤会议中真值"李笑康"83 段被预测为"贺文泰"（0.5 口径最大错名对）。两人语音被在线聚类以余弦距离 0.8 阈值并入同一全局簇，质心以多数方贺文泰为主导，确认器按设计输出簇内主导人名。**根因**：聚类合并；**对策**：降低 delta_new 至 0.5–0.6 或为低注册量说话人补充注册样本。

**案例 2（误报，陌生人并入注册簇）**：项目进度会议真值"陌生人5"→"张旭"误报由 0.4 口径的 59 段降至 0.5 口径的 8 段（-86.4%；会议误报合计 69→18，-73.9%）。残余 8 段为聚类将陌生人语音并入张旭簇后质心相似度仍 ≥0.5 的情况。**根因**：聚类层未区分陌生人；**对策**：进一步提高阈值或以聚类层解决（已知局限）。

**案例 3（漏报，碎片簇）**：项目进度会议"张旭"87 段预测为空（0.5 口径该会议漏报合计 106 段）。说话人被聚类分裂为多个短簇，各簇语音量不足、质心相似度低于 0.5，确认器按设计不命名。**性质**：确认器保守行为（宁缺毋滥），符合"未注册不替换"要求；**代价**：召回损失。

## 5. 结果总结

**核心结论**：
1. **流式说话人确认功能成立且可实时运行**：CPU 下 0.11s/chunk（实时比 0.22x，约 4.6 倍实时），WebSocket 全链路实测确认人名随流输出，确认延迟 2–5s。
2. **段级准确率 71.4%**（EER 校准阈值 0.5，较经验值 0.4 提升 11.8pp），但**上限受聚类质量制约而非确认器**：错名/漏报合计占错误 86.2%，根源为聚类合并/碎片化，确认器对纯净聚类的命名正确（同人/异人对 EER 仅 0.6%）。
3. **未注册说话人保护有效**：未达标不替换、误确认自动撤销（组件级验证通过），符合"未注册不替换标签"的要求。
4. **调参方向明确**：EER 校准阈值（0.5）优于经验值（0.4）；delta_new 从 1.0→0.8 单会议提升约 10 个百分点。

**决策建议**：
1. **可交付使用**：功能已集成 serve（WebSocket）/stream（命令行）双入口，推荐以 `delta_new=0.6~0.8、threshold=0.5`（EER 校准值，已设为默认）参数上线；保守场景可上调至 0.55。
2. **优先改进聚类而非确认器**：后续投入建议聚焦在线聚类对 wespeaker 向量的适配（delta_new 自适应、同人簇合并），预计对准确率的边际收益最大（当前 86.2% 错误源自聚类层的合并/碎片化）。
3. **注册侧投入**：为仅 1 段注册音频的说话人（刘磊/王倩婷/黄婷）补充样本，与准确率正相关（4.2 推断，需扩充样本后验证）。
4. **生产部署注意**：启动含声纹注册耗时 30–60s（CPU）；声纹库热更新暂不支持，需重启服务。
